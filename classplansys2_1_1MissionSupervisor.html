Detailed Description

Plans, executes, and plans again when execution fails.

The loop every mission on hardware needs and every demo used to write for itself: ask for a plan, run it, and when an action fails ask again rather than stopping. The planner is asked against the problem as it now stands, so the next plan starts from where the mission got to. With the epistemic solver this includes what the robots have learned: the epistemic state publishes the belief the mission reached, the solver plans from it, and a scan that already happened is not planned for twice.

It needs nothing epistemic and works the same over a classical solver; what the epistemic stack adds is a belief worth replanning from.
